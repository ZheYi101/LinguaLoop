# Project Brief

## 一句话定位

LinguaLoop 是一个把沉浸式输入转化为语音输出练习的开源语言学习伙伴：用你已经看过、听过、读过的内容作为共同语境，让 AI 陪你聊起来。

**项目主旨：沉浸提供语境，LinguaLoop 帮你练输出；语音对话是核心体验。**

本文是当前产品定位的权威入口；MVP 边界见 [MVP Spec](./MVP_SPEC.md)，当前分工、证据与交付状态统一见 [Roadmap](../planning/ROADMAP.md)。MD3 桌面与分轮语音接口已有早期实现，历史状态见 [初版记录](../planning/INITIAL_VERSION_2026-10-24.md)。本轮按用户明确要求先完成双模型纯文本能力与真实服务测试，再尝试 LiveKit 实时语音；完整 MVP 仍需独立语音验收。

## 为什么做

这个想法来自用户已有的语境练习 skill：下载最近看过的视频字幕，把字幕构成语境，再围绕语境训练。单独生成语境练习没有满足用户的需求；转向沉浸式学习后，新的方向是把二者结合起来。

学习者继续按自己的兴趣看番、追视频、听播客或读文章。LinguaLoop 接住这些已经发生的输入，用共同内容减少“找 AI 不知道聊什么”的阻力，并提供用户特别重视的语音对话练习机会。

输入和输出在这里分工：沉浸提供内容、兴趣与语境，项目提供围绕这些内容开口、互动、获得反馈和再次尝试的空间。学习收益仍是待验证的产品假设，不能把这段个人经历当成普遍有效性的证据。

## 目标用户

- 已经通过动画、视频、播客、文章等内容进行沉浸输入的学习者。
- 对内容有兴趣，但缺少口语伙伴，或不知道如何从输入转到表达的人。
- 希望 AI 先了解自己接触过的内容，再一起讨论的人。
- 想调整练习方式、反馈节奏，并逐步尝试自己认可的学习理论的人。

## 核心体验

1. **带入沉浸语境**：用户看完一集动画或一段视频，提供对应字幕、转写或文本，并说明本次想聊的内容范围。材料可以来自同一系列，但无需先整理完整系列才能开聊。
2. **AI 先理解材料**：推理模型将内容整理为规范化片段、故事大纲、人物和丰富话题库；每题提前准备常见用户回应分支、简短回答要点、追问和来源依据，覆盖故事核心、角色与动机等角度。内容不足时明确边界，不为增加题量虚构材料。
3. **选一个话题就开口**：先选择材料，再选预制话题；自定义题由推理模型现场准备。实际对话只由快速对话模型回应。自然讨论是默认入口，不要求先完成词汇讲解、理解测验或整套课程。本阶段先用文字验证，后续接语音。
4. **可选语境 roleplay**：愿意扮演时，用户可以进入材料启发的场景，以某个角色或身份互动；不把角色扮演设为开聊前提。
5. **按需反馈与复盘**：根据用户选择的纠错强度，在合适时机给提示、替代表达或结束后的重点反馈，将值得再练的输出问题留到下次。

例如：看完一集动画后，AI 可以围绕已导入的字幕问“你理解这个角色为什么这样做吗？”；用户也可以选择“如果换成你，会怎么回应？”来聊自己的观点，或自愿进入同类场景 roleplay。

## 核心原则

- 沉浸与输出互补：围绕用户已有的输入安排对话，不要求用户改变原来的内容消费习惯。
- 语音优先：语音对话是核心产品验收项；文本承担原型验证、辅助输入和故障回退，不能替代语音体验的验收。
- 话题先行：先帮助用户找到想聊、能聊的事情；词汇提取、理解检查和复述按需使用。
- 语境可信：话题应关联已提供的材料；只有字幕时，不假装理解未提供的画面、音效或后续内容。
- 提前准备服务于迅速回应：推理角色持续按需整理当前进度、预测可能回应并准备材料；对话角色不等待背景推理。预测只作为候选，不得冒充用户真实表达或覆盖当前输入。
- 延迟如实验收：用户提出对话模型完整运行时间小于 1 秒的优化目标。模型首字、完整回复和 UI 端到端分别测量；流式首字达标不等于完整回复达标。用户随后明确同意：文本功能通过后可先做 LiveKit 本地探针，1 秒不再阻止该探针；已有未达标事实继续保留。
- roleplay 自愿：自然讨论与角色扮演共享语境，但用户可以只讨论内容。
- 反馈服务于继续表达：纠错不只告诉用户错了什么，还要给出下一次可用的表达，并允许集中到结束后反馈。
- 输出才是证据：只有用户真实回答、冷启动输出、复习结果或延迟检索能更新学习状态；展示过内容不等于已经掌握。
- 方法可调整：目标、难度、纠错时机和练习节奏应可调；长期允许通过 Pattern 配置或扩展用户认可的学习方法，完整自定义理论系统不作为当前 MVP 前提。
- 数据可迁移：作为开源项目，用户学习数据应尽量避免被某个服务锁死。

相关依据见 [Learning Loop Foundation](../research/LEARNING_LOOP_FOUNDATION.md) 和 [Practice Workspace Findings](../research/PRACTICE_WORKSPACE_FINDINGS.md)。

## 产品范围与现有基础

当前已有 Python core、CLI、MD3 桌面、话题讨论、本地持久化与复习队列，已接入可替换分轮语音接口。本轮实现范围是材料与对话两个主要入口、DeepSeek 推理/快速对话角色、提前准备及后台整理；已完成能力必须以代码和 Roadmap 的验证记录确认。复盘附属于对话，设置属于辅助入口。

正式 MVP 仍需实际完成“沉浸材料理解 → 话题选择 → 至少三轮真人实时语音 → 轻量复盘”。文本阶段验收通过后，用户指定采用 LiveKit 实现连续对话、流式音频和打断；已有分轮录音是开发回退。STT、TTS 继续独立可替换，模型保持云端，本地语音包只作可选候选。服务研究与文本门槛见 [服务选型](../research/SERVICE_SELECTION_2026-10-24.md)。

用户后续明确继续解决本机 RTC 连接超时，先验证真实连续 PCM、取消后旧帧阻断及重入，再推进流式 STT/TTS。连续语音必须由用户明确开始；partial 只作预览，final 按会话端点策略确认后驱动对话。云端识别/合成、本地音轨传输和设备可听播放分别验收，不能用其中一项代替其他项。当前语音凭据是否存在、后续接入契约与无新增费用的 mock 路径见 [流式接入增量](../research/SERVICE_SELECTION_2026-10-24.md#后续增量rtc-通过后的最小流式语音接入)。

## 非目标

- 不做泛用聊天机器人。
- 不把沉浸内容默认改造成必须学完的课程或题库。
- 不要求用户接受 roleplay 才能练口语。
- 不建设视频播放平台、自动抓取整部版权作品或完整自定义学习理论编辑器。用户授权的本地小说、表格文本、字幕和视频材料导入属于产品方向；具体格式和长度限制以当前实现为准，无法提取时要说明原因。
- 不在第一版实现完整课程市场。
- 不在第一版覆盖所有语言学习场景。
- 不把自动评分包装成绝对能力评估；第一版只提供辅助性反馈。

## 待验证与后续设计

- 话题是否能让用户愿意开口、持续讨论，以及对话是否持续锚定材料，需要真实使用验证。
- 文本阶段将材料分析与后台准备移出回应关键路径，但预制内容能否提升自然度、命中率和完整回复速度必须通过真实 API 测量。
- 语音阶段使用 LiveKit；国内 STT/TTS 候选需核实日语能力、流式/取消、凭据分发、地域与计费，再做实际使用测试。官方能力说明不能替代国内稳定性或延迟验证。
- 本阶段逐轮推理纠错暂停，反馈集中在结束后或关闭；旧会话的 immediate 偏好要明确提示改为结束后，不让推理调用阻塞实际回复。
- 学习理论配置先保留为产品方向；可配置字段、导入方式和扩展权限需后续定义，不能将任意理论描述直接视为有效学习流程。

## 主旨修订记录

- **2026-10-24 RTC 后续目标**：用户要求继续修复本机连接，先真实跑通连续音轨与打断，再推进 STT/TTS。保留既有文本与 RTC 失败证据，不以离线测试或旧候选包代替新真实验收；服务未配置时可以先做 fake WebSocket/Mock LLM 接线，但不宣称真实语音服务可用。

- **2026-10-24 双模型迭代**：依据用户明确要求，聚焦材料与对话；材料预制丰富话题/回答依据，DeepSeek Pro 做准备、Flash 做实际回应，并后台按需整理。先真实文本验证（保留完整回复小于 1 秒的性能目标），之后才实现 LiveKit 实时语音。国内中日语服务、本地语音包和多用户分发方案分开调研与验收。

- **2026-10-24 验收口径明确**：用户实际选择“1 秒保留为优化目标，文本功能通过后先做 LiveKit 探针”。该决定替代本轮早先将完整回复 1 秒作为 LiveKit 硬门的规则，不改变历史测量结果；本地探针不代表公网、真人语音或商用验收通过，状态见 Roadmap E32。

- **2026-10-24 初版实现**：采用 MD3 桌面和独立分轮 STT/TTS，新增话题与会话偏好。代码和模拟语音路径已有验证，真实三轮语音仍待单独验收，见 [初版记录](../planning/INITIAL_VERSION_2026-10-24.md) 与 Decision 0011。

- **2026-10-24**：依据用户本次明确提出的 idea，将主旨收敛为“沉浸提供语境、语音对话练输出”；话题推荐成为主要入口，roleplay 保持可选，学习方法可配置保留为后续方向。同步调整 MVP 和路线图中的语音优先级，见 [Decision 0010](../decisions/TECH_DECISIONS.md#decision-0010-沉浸语境驱动语音输出成为产品主线)。
