# MVP Spec

## MVP 目标

第一版目标是验证“沉浸提供语境、语音对话练输出”：用户带入已经接触过的材料，AI 先理解内容并推荐话题，用户选一个话题完成多轮语音讨论，结束后获得轻量、可追溯的复盘。

产品定位见 [Project Brief](./PROJECT_BRIEF.md)。本文件描述目标范围，实际执行状态与证据统一见 [Roadmap](../planning/ROADMAP.md)；[初版验证记录](../planning/INITIAL_VERSION_2026-10-24.md)保留为历史快照。本轮用户明确调整交付顺序：先双模型纯文本开发与真实 API 验证，之后尝试 LiveKit 连续实时语音。文本阶段不要求 STT/TTS 配置，也不因此宣称完整语音 MVP 完成。

## 核心流程

1. 用户提供看过的动画、视频、播客或文章对应的字幕、转写或文本，确认标题、语言和本次讨论范围。
2. 推理模型理解材料，整理规范化片段、大纲、人物和丰富话题，每题预制常见回应分支、可用回答要点、追问及引用。词汇和表达分析按需查看。
3. 用户先选择材料，再选题；自定义题先由推理模型现场准备。调整难度与反馈偏好，开始讨论；也可以自愿选择语境 roleplay。
4. 快速对话模型执行所有实际回应；推理模型根据进度按需在后台准备后续依据，不能阻塞回应或把预测当已确认用户输入。当前阶段文字交互，文本验收后以 LiveKit 接入流式语音、轮次检测和打断。需要时可查看转写、输入文字或请求提示；不强制先完成理解测验或固定 lesson。
5. 用户主动结束练习后，系统生成复盘：表现摘要、错误类型、推荐表达、复习项和下一次任务。
6. 复习项保存到本地 review queue，下次启动软件仍可查看并继续复习。

## MVP 功能范围

- 材料管理：创建、查看、导入沉浸内容，已有 TXT、Markdown、DOCX、SRT、VTT；本轮向小说/EPUB、Excel 表格文本及本地视频材料扩展。保存 raw/normalized 与来源片段；视频优先提取已有字幕，缺字幕/工具/转写服务时明确提示，不能伪装理解画面。具体已支持格式、长度、转写条件以代码和 README 为准；不静默截断整本材料。
- 语境与话题：大纲、人物、规范化片段、丰富话题和开场问题。每题准备常见用户回应分支、简易回答要点、可接续追问与源文依据；可自提题并由推理现场整理。题量受真实内容支撑，不重复凑数。
- 真实长篇验收：以用户实际提供的完整小说验证分段准备、整书汇总和结局覆盖，再以读者身份讨论具体情节、人物动机、叙述视角、分歧和改口。回答应接续实际线程并有准备资料支撑；非空文本、泛泛认同或单个短篇不能代替这项验收。首字与完整回复分别计时，1 秒作为持续优化目标。
- 双模型讨论：DeepSeek 推理角色处理材料与背景准备，快速非思考对话角色处理每次实际回复。流式显示，记录首字与完整回复耗时；自定义题准备有独立进度和重试。
- 后台准备：按 session/topic/turn 修订更新有限候选，合并重复任务、丢弃过期结果、取消退出任务；背景失败不阻断快速模型或丢失消息。预测是候选信息，不是用户事实。
- 语音讨论：文本验收通过后采用 LiveKit 连续实时交互，包含流式 STT、流式 TTS、轮次与用户打断；转写查看、文字补充、失败恢复保留。现有分轮录音仅作开发回退，不能替代用户指定的实时体验。
- 可选 roleplay：用户主动选择后设置角色和场景，沿用同一材料语境；默认仍是自然讨论。
- 反馈：默认低强度、结束后集中反馈，可关闭。本阶段暂停逐轮推理纠错；历史 immediate 偏好明确提示延后结束，实际回复不等待推理。低/中/高强度最多保留 1/2/3 个有输出证据的重点，复习项最多三个，证据不足可为空。
- 练习复盘：会话摘要、错误记录、推荐复习项，结束会话时集中生成 review candidates。
- 本地持久化：用 SQLite 保存材料、会话、消息、反馈、复盘和 review queue。
- 基础复习：支持 `again`、`hard`、`good`、`easy` 结果记录和简单 due date 更新。
- 基础设置：目标语言、用户母语、难度、纠错强度和反馈时机。
- 最小扩展基础：材料话题讨论 Pattern、可选 roleplay、可替换 LLM / voice provider 边界、必要的 capability 检查和 provider mock；完整插件生态不阻塞核心语音路径。

## 学习方法约束

MVP 不需要一次性实现完整课程系统或 SRS，但必须体现以下学习闭环约束：

- 输入材料需要进入可教学状态。至少要区分 raw text、lesson-ready text 和后续 segment；不要直接从带时间戳、断行、重复 cue 或明显 ASR 噪音的字幕中抽取练习目标。
- `track` 是显式业务属性，不应只由文件后缀推断。`live_chat` 更关注互动语气和口语 chunk；`article_reading` 更关注论点、连接词、概括和改写精度。
- 用户已完成的沉浸输入可以直接成为共同语境。理解检查、词汇讲解和复述按需提供，不作为进入语音讨论的必经步骤。
- 话题和追问应锚定用户提供的内容范围；只有字幕时不能假装掌握未提供的画面或后续情节。材料不足时说明不确定性，让用户补充或缩小范围。
- 每次练习必须包含一个主动输出动作，例如改写、复述、场景对话或短 summary；只展示解释不算完成学习闭环。
- 反馈必须关联到用户真实输出或源材料片段，优先记录反复出现的 pattern-level 问题，而不是堆叠所有小错。
- 复盘以结构化 review candidates 保存，证据不足允许空列表；第一版实现简单 `due_at` 和 `status`，为后续 spaced review 留接口。
- Profile Delta 只能表示本轮学习证据，不能把一次回答包装成长期能力结论。
- 语音转写可能出错，应允许用户确认或修正；不能仅凭转写文本诊断发音问题，也不能把识别错误直接记为学习错误。原始录音不作为完成复盘的必要存储项。
- 用户自选学习理论的方向通过可配置练习与 Pattern 扩展逐步承接；MVP 先提供基础偏好，不要求完整理论导入器或编辑器。

理论和实践依据见 [Learning Loop Foundation](../research/LEARNING_LOOP_FOUNDATION.md) 与 [Practice Workspace Findings](../research/PRACTICE_WORKSPACE_FINDINGS.md)。

## 暂不包含

- 在文本验收之前实现或部署实时语音；完整语音质量评分、多人通话与电话网络仍不包含。连续实时与用户打断已由本轮用户纳入后续语音阶段目标。
- 视频播放平台、自动下载整部作品和跨整季内容的自动索引。
- 完整自定义学习理论编辑器、任意方法自动编译和方法有效性自动认证。
- 移动端原生应用。
- 多人社区、排行榜、课程交易。
- 完整 SRS 算法。
- 复杂教师后台。
- Live2D / avatar 渲染；作为后续表现层插件验证。

## 用户故事

- 作为学习者，我看完一集动画后，可以提供字幕，让 AI 理解我刚接触过的内容。
- 作为学习者，我可以从几个有材料依据的话题中选一个，通过语音聊观点、角色或自己的经历。
- 作为学习者，我不想扮演角色时可以直接讨论，想尝试时也能自愿进入语境 roleplay。
- 作为学习者，我可以在语音失败时保留当前会话，通过重试或文字补充继续练习。
- 作为学习者，我可以控制 AI 纠错强度，避免对话被频繁打断。
- 作为学习者，我可以在结束后看到我常犯的错误和下一次该练什么。

## 初始数据对象

以下对象沿用现有领域边界；新增字段使用默认值兼容历史 payload，语音状态留在桌面 ViewModel，不存原始音频。

- UserProfile: 用户语言、目标、偏好设置。
- LearningMaterial: 标题、语言、来源、正文、分析结果。
- DiscussionTopic: 标识、标题、类别、开场问题、源文依据及预制回应分支/回答要点；旧 payload 字段默认兼容。
- Material preparation: 材料规范化片段、大纲、人物与覆盖范围；后台准备持有 material/topic/session/turn 修订和候选内容，不能冒充确认消息。
- PracticeOptions: 自然讨论/roleplay、难度、纠错强度、时机与角色描述。
- SubtitleCue: 原始字幕起止毫秒和文本。
- PracticeSession: 材料、目标、难度、消息列表、状态。
- Message: 角色、内容、时间、反馈引用。
- FeedbackItem: 错误类型、原句、建议句、解释、复习状态。
- LearningSegment: 材料片段、来源位置、上下文和练习目标。
- ReviewItem: 表达、例句、来源会话、来源材料、状态、下次复习时间。
- ReviewOutcome: 复习回答、结果评级、发生时间和下一次复习时间。
- SessionReview: 会话摘要、重点问题、review candidates 和下一步建议。
- SessionEvent: 会话中可追踪、可回放的学习事件。
- PracticePlan: 学习 Pattern 生成的一次练习计划。

## 验收标准

- 本轮文本阶段先执行材料分析、预制题与自定义题、至少三轮真实日语对话、后台准备/失败恢复及重启恢复；mock 和真实 API 分开报告，语音阶段在文本门通过后开始。具体 gate 见 [服务研究](../research/SERVICE_SELECTION_2026-10-24.md#文本验收门与有界素材)。
- 对话前台调用只由快速非思考模型执行，不等待后台推理或逐轮纠错；显式测试后台失败、过期结果、改口、未预测回答和材料内嵌指令。
- 用户提出模型完整回复小于 1 秒的性能优化目标；分别记录 provider 首个可见 token、完整回复、UI 首字与完成。未达标必须标明，不用首字替代完整回复，也不将准备耗时藏入计时起点。用户后续已明确允许文本功能通过后先做 LiveKit 本地探针，因此 1 秒不作为阻止探针的硬门；保留其余正确性、引用和数据边界要求，见 Roadmap E32。
- 用户可以查看材料大纲/人物与丰富话题、常见回答要点及引用；自定义题能现场整理，材料支撑不足时明确说明。长篇材料的覆盖范围可核对，不静默丢弃后文。
- 用户可以完成“沉浸材料 → 话题选择 → 多轮语音讨论 → 结束复盘 → 后续复习”的端到端流程；仅文本链路通过不算完成正式 MVP。
- 用户可以导入 `.txt`、`.md`、`.markdown`、`.docx`、`.srt` 和 `.vtt`，保留 raw/normalized 文本边界及字幕时间信息。
- 系统提供多个可聊话题、开场问题和可追溯的材料依据，用户可以选择、修改或自提话题。
- 用户不必完成词汇课、理解测验或 roleplay 就能开始讨论；主动选择 roleplay 后可进入明确角色和场景。
- 语音阶段用户至少能在 LiveKit 连续完成三轮语音交流并听到流式回复，能打断播放后继续讨论；可查看识别文本并补充修正。另测停顿、回声、断网、设备切换和资源清理；文字回退不计作语音通过。
- 用户新增后续目标先解决本机 RTC 超时，真实验证连续 PCM、取消后零旧帧呈现和重入，再推进 STT/TTS；旧离线测试、包完整性或合成帧不能代替这些新真实验收。无语音凭据时可先 fake WebSocket/Mock LLM 接线，不算真实识别或合成通过。
- 连续语音由显式开始操作启用；STT partial 只作预览，final 按当前模式确认并按 utterance ID 去重后驱动对话。打断关闭旧回复代际并清传输/设备队列，继续接收新的发言；应用需明确 pending 转写与已保存消息，不能把被取消的半段 assistant 当完成历史。
- 麦克风、识别或播放失败时显示可理解的状态，保留已确认消息和当前会话，允许重试或切换文字；文字回退不计作语音验收通过。
- 对话内容能稳定引用材料语境，不退化成泛用聊天。
- 反馈强度和时机可控，结束后集中反馈时不在每轮强制插入长篇批改。
- 复盘内容以结构化数据保存，而不仅是纯文本总结。
- 会话未结束前不生成最终 review queue；用户主动结束后才集中生成复习项。
- 重启软件后仍可看到已保存材料、会话摘要和 review queue。
- 用户可以对复习项记录 `again`、`hard`、`good`、`easy` 并更新下次复习时间。
- LLM 调用失败时有可理解的错误提示，不丢失用户当前输入。
- 用户数据和配置不依赖硬编码示例。
- 内置学习 Pattern 通过稳定 contract 生成练习计划和复盘草稿，并声明所需 capability。
- 系统不会把“生成过 lesson”或“展示过复习项”计为掌握；只有用户输出、复习结果或延迟检索结果能更新学习状态。
- Review 入口默认 summary-first，先给 1-3 个复习方向，再按需展开具体条目。
- UI 统一采用 MD3，支持系统/浅/深主题、减少动效、键盘操作，以及 360/600/800/1180/1440px 布局；新增组件、图标与许可证包含在 wheel 中。
- UI 聚焦材料、对话两个主要入口，复盘附属对话、设置作为辅助；Windows 原生标题栏由应用自绘替代，同时保留拖动、最小化、最大化/还原、关闭和调整尺寸。
