# LinguaLoop UI 页面规划

## 方向

桌面端和 Android 端共享 PySide6/QML 页面，基础控件使用 Qt Quick Controls 6，应用壳使用 Kirigami。移动端不是桌面三栏布局的窄化版本，而是围绕当前学习动作的单列流程：

```text
材料 -> 分析 -> 练习 -> 用户输出 -> 反馈 -> 复盘
```

## 页面

### 材料

用户输入标题、正文、材料语言、目标语言、母语和等级。点击分析后展示摘要、关键词、表达、难点和推荐目标，再进入练习。

桌面端可以在主区域展示编辑器和分析结果；移动端使用单列表单和可滚动分析结果。

### 练习

展示当前任务、对话记录和输入框。发送期间显示 loading，重复提交被禁止；请求失败时保留用户输入并展示错误。桌面端可显示材料上下文，移动端优先保证对话和输入区域可用。

### 复盘

展示会话摘要、反馈项和 review items，并提供 JSON 导出。桌面端可同时展示更多细节；移动端默认先展示摘要和重点项，详细内容通过滚动查看。

### 导航和设置

第一版导航为材料、练习、复盘和设置占位入口。桌面端使用侧栏或页面导航，移动端使用 PageStack/Drawer。设置页暂不实现 provider 配置和持久化设置。

## CLI 映射

| CLI 命令 | 页面能力 |
| --- | --- |
| `load` | 材料页创建和分析 |
| `start` | 从材料页进入练习页 |
| `say` | 练习页发送回答 |
| `review` | 复盘页复习项 |
| `summary` | 复盘页摘要 |
| `export` | 复盘页导出 |
| `reset` | 应用级重置 |

首版不做完整课程、账户、数据库、语音、历史搜索和完整 SRS 调度。

## UI 边界

QML 只依赖 Python ViewModel 的 properties、signals 和 slots。ViewModel 调用 `LearningWorkbench`，将 Pydantic 对象转换为 QML 可用的稳定 DTO。网络请求不阻塞 UI，错误不丢失输入。
