# 初版实施与验证记录（2026-10-24）

## 本次实现

首版主线为“导入沉浸内容 → 推荐话题 → 选择话题 → 分轮语音讨论 → 轻量复盘”。技术方案见 Decision 0011，界面规范见 [MD3 页面方案](../product/UI_SURFACE_PLAN.md)。

| 增量 | 实现状态 |
| --- | --- |
| 线程、SQLite、主题 | SQLite 按操作连接和事务；一个后台 asyncio worker；AppTheme、MD3 组件和系统/浅/深主题 |
| 材料和话题 | TXT/Markdown/DOCX/SRT/VTT；先保存后分析；原文/清洗文本/cue 时间；源文引用校验与有限重试；自然讨论和可选角色 |
| 分轮语音和恢复 | Qt WAV 录放音、60 秒上限、独立 STT/TTS 配置；可编辑转写、重录、取消、停止/重播；分别重试失败步骤 |
| 复盘和打包 | 默认结束反馈；只保留实际输出证据，最多三个重点/复习项；复盘导航与 SQLite 恢复；wheel 纳入 QML、qmldir、SVG、许可证 |

录音和播放对象属于 GUI 线程，模型调用复用后台 event loop。合成失败不会重复用户消息。未确认的草稿不写数据库，正常退出清理临时音频。历史 payload 使用兼容默认值；旧会话的 options 为空时保留原有语义。

## 自动验证

使用 `RUN_REAL_AI_TESTS=0` 的离线 pytest。覆盖材料解析、话题引用、Prompt 边界、结构化失败重试、旧数据默认值、跨线程 SQLite、独立语音适配器和失败恢复。

Qt Test 使用真实 QML 控件点击选择话题、开始、录音、停止、编辑转写、发送和结束；注入假音频设备与合成 WAV，连续完成三轮并核对七条已确认消息、话题及复盘重启恢复。覆盖 STT、文本生成、TTS 和播放失败，重复提交与正常退出清理。

检查 360、600、800、1180、1440px 下系统/浅/深主题、中文与日语长草稿、导航切换、48px 交互区域、填充按钮文字对比度、键盘焦点与渲染。`scripts/render_ui_preview.py` 显式加载 Windows 字体，生成 1440px 明暗、1180px 材料、800px、360×800、360×560、复盘与明暗设置页共九张截图，不读取用户数据。

构建命令：`uv build --wheel --out-dir build/package-check`。资源在 wheel 中验证，另从 wheel 的临时安装目录加载 QML 作启动检查。此处验证的是 Python wheel，不是独立 Windows 安装器。

- 离线回归：**70 passed，1 skipped**；跳过的是显式启用的真实 AI 测试。
- wheel 构建成功；`scripts/check_wheel_resources.py` 检查 **36 个 QML/图标/许可证资源**，并从 wheel 临时目录成功启动 QML。
- 当前 Windows 环境可见 **3 个输入、5 个输出设备**；STT 和 TTS 环境配置均不完整，未发起真实音频服务请求，也未进行真人录音。
- `git diff --check` 通过。

## 真实语音验收与剩余限制

真实麦克风和服务三轮验收仍未完成，不能标记正式语音 MVP 验收通过。需配置 `LINGUALOOP_STT_*`、`LINGUALOOP_TTS_*`，按 [语音指南](../desktop/VOICE.md) 在可见 Windows 窗口进行实际发言和收听。设置显示配置状态，不能保证供应商端点实际可用。

当前还有以下边界：

- 长材料单次分析最多 30000 字符，需带入本次片段；没有整季索引或自动视频下载。
- 直接修改已有话题、材料原地编辑/删除、完整理论编辑器、连续语音/自动打断、移动端和独立安装器留到后续。
- 字幕保留 cue 时间，话题先以精确引文回溯到材料；尚无视频时间轴跳转或完整场景索引。
- mock 能验证状态和存储，无法验证真人可听性、话题质量、口音识别效果、云服务延迟或成本。
- 程序被强制终止时可能留下临时文件；外部服务对数据的保留策略由所选服务决定。
